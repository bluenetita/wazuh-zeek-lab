# Client Linux

`Client-Linux` is the primary Linux endpoint on VLAN 20 and participates in several cyber-range scenarios.

## Network

| Field | Value |
|---|---|
| Primary IP | `10.3.20.2/24` |
| VLAN | 20 - Client |
| Gateway | `10.3.20.1` |
| SSH role | A1 |

A clone, `Client-Linux2` (`10.3.20.4`), is used as A2 in SSH tests with independent sources.

Traffic toward the Server VLAN passes through RouterOS; traffic toward the simulated external network continues toward pfSense. Sanitized netplan files already present in the directory remain valid as a reference for the primary endpoint.

## Role in the scenarios

Client-Linux is used for:

- legitimate client traffic;
- controlled reverse-shell activity and Zeek/Wazuh correlations;
- host-based Auditd events;
- privilege escalation in the corresponding scenario;
- authorized scanning;
- A1 source in multi-host SSH tests;
- RouterOS quarantine validation during the Active Response campaign.

## Relationship with Zeek

When traffic crosses the mirror point, Zeek can observe connections, DNS, HTTP/TLS, and events generated by the custom scripts.

## Wazuh and Auditd

Updated configuration:

```text
blue-team/wazuh/agent-configs/client-linux-agent-ossec.conf
```

Auditd events relevant to reverse-shell correlation are enriched with the host IP. The Manager decoder uses that information together with network telemetry.

## Active Response

During the ON campaign, IP `10.3.20.2` was observed in the `Quarantine` list and the expected TCP probe toward `10.2.0.2:22` was blocked. This behavior was not observed in the OFF runs.

Quarantine removal was performed by the campaign coordinator; it is not automatic rollback implemented by the script.

## Note

Client-Linux represents a simulated enterprise endpoint, not a generic vulnerable machine. Offensive activity documented here is limited to the isolated cyber range.
